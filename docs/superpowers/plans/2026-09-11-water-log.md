# Water Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two-tap water logging page in MyFitnessClone that writes `water_log.csv`, plus a daily water gauge on the Health-Tracker dashboard.

**Architecture:** Static HTML pages commit rows straight to `main` via the GitHub contents API (same as the food log). A tiny Python generator turns the log into a per-date CSV; a workflow runs it and dispatches `water_updated` to Health-Tracker, which fetches the per-date CSV as a third source, appends it to the master table, and renders a fill-circle.

**Tech Stack:** Vanilla HTML/CSS/JS, Python 3.11 stdlib (`csv`, `argparse`), pytest, GitHub Actions, Chart.js (already vendored in Health-Tracker).

**Spec:** `MyFitnessClone/docs/superpowers/specs/2026-09-11-water-log-design.md`

## Global Constraints

- Bottles: `big` = 32 fl oz, `small` = 26 fl oz. Goal: 128 fl oz per day. Units are fl oz everywhere.
- `water_log.csv` is append-only. Undo deletes a row; nothing ever edits a number.
- Both repos have uncommitted work from other sessions. Commit with explicit pathspecs only (`git commit <paths>`). Never `git add -A`.
- Pages write with the existing localStorage keys `gh_token`, `gh_owner`, `gh_repo`. No new keys.
- All data files stay flat at the repo root (workflows hard-code root paths).
- Health-Tracker column layout is `[whoop][spacer][meal]` today; water is appended after, never inserted before.
- Windows dev box: Python 3.12 locally, 3.11 in Actions. No `&&` in PowerShell. Use the Bash tool for shell.
